# One SQLite store per project folder under ~/.dotweavier; never write inside a project

dotweavier must leave no trace in tracked repositories, so all state lives in `~/.dotweavier`: no config files, ignore entries or generated files in projects. A workspace is the folder that projects are found under. Registered workspaces are rows of a `workspaces` table in `~/.dotweavier/dotweavier.db`, and they may nest. Each project folder has exactly one SQLite store, `~/.dotweavier/projects/<folder path>.db`, shared by every workspace that contains the folder; each workspace names the project by its path relative to itself when it loads the store. Two separate indexes of one project therefore need two copies of it, such as two clones or worktrees. `trace` loads only the projects it needs into an in-memory graph for path search. We chose SQLite over JSON files (as graft and graphify use) because it can be queried without loading everything, updated incrementally, and reused by the future UI. gortex and codebase-memory-mcp make the same choice.
