# One SQLite store per project folder under ~/.dotweavier; never write inside a project

dotweavier must leave no trace in tracked repositories, so all state lives in `~/.dotweavier`: no config files, ignore entries or generated files in projects. A workspace is a name with one or more registered folders; its projects are the ones found under them. The folders of every workspace are rows of a `workspace_folders` table in `~/.dotweavier/dotweavier.db`, and folders may nest. Each project folder has exactly one SQLite store, `~/.dotweavier/projects/<folder path>.db`, shared by every workspace that contains the folder; each workspace names the project by its path relative to the deepest of its folders that contains it when it loads the store. Two separate indexes of one project therefore need two copies of it, such as two clones or worktrees. `trace` loads only the projects it needs into an in-memory graph for path search. We chose SQLite over JSON files (as graft and graphify use) because it can be queried without loading everything, updated incrementally, and reused by the future UI. gortex and codebase-memory-mcp make the same choice.
